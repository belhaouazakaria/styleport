# Proposed Growth data model (Phase 1 contract)

No schema or migration is created in Phase 1. Names below are proposed Prisma names. Use existing `cuid()` IDs, uppercase Prisma enums, `createdAt @default(now())`, `updatedAt @updatedAt`, explicit foreign keys/delete actions and timestamped migrations. Money: `Decimal(12,6)` or higher precision for unit costs; never floating point. `Json` stores bounded evidence/variants/snapshots, not an unbounded generic event log. Every state transition writes `GrowthActivity` in the same transaction where possible. Restrict deletion of audit, publication, cost and conversion history; scrub sensitive payloads by retention job. All Growth relations to Translator/User use `onDelete: SetNull` for durable history; do not cascade away evidence.

## Enums and transitions

- `GrowthAccountIntent`: `UTILITY`, `INSPIRATION`, `PLAYGROUND`; `GrowthConnectionStatus`: `PENDING`, `CONNECTED`, `REAUTH_REQUIRED`, `DISCONNECTED`.
- `GrowthOpportunityStatus`: `OPEN -> EVALUATING -> ACTIONED | DEFERRED | DISMISSED`; `DEFERRED -> OPEN`; any nonterminal -> `CANCELLED`; errors -> `FAILED_RETRYABLE -> EVALUATING | FAILED_TERMINAL`. A new evidence window creates a new opportunity/version, never mutates a closed explanation.
- `GrowthDecisionStatus`: `PROPOSED -> VALIDATING -> EXECUTING -> COMPLETED`; validation may yield `WAITING_DATA`, `REJECTED`, or `CANCELLED`; failure `FAILED_RETRYABLE -> EXECUTING | FAILED_TERMINAL`. `NO_ACTION` is a completed decision with reason.
- `GrowthPinCandidateStatus`: `DRAFT -> READY -> AWAITING_APPROVAL -> APPROVED -> QUEUED`; alternate `DEFERRED -> AWAITING_APPROVAL`, `REGENERATING -> DRAFT`, `REJECTED`, `EXPIRED`, `CANCELLED`, `FAILED_TERMINAL`. An edit/regenerate creates a revision and invalidates prior approval.
- `GrowthPinApprovalStatus`: `PENDING -> APPROVED | REJECTED | DEFERRED | SUPERSEDED`; deferred can return to pending; each approval is tied to exact immutable candidate revision, image checksum, title/description/destination/account/board/time checksum and approver User. Approval cannot authorize a changed candidate. Future publishing mode is disabled by default and requires separately recorded authorization/policy change; it never silently creates approval rows.
- `GrowthPublicationStatus`: `SCHEDULED -> CLAIMED -> PUBLISHING -> PUBLISHED -> RECONCILED`; timeout/unknown result -> `RECONCILING`, never blind retry; `FAILED_RETRYABLE -> SCHEDULED | FAILED_TERMINAL`; `CANCELLED` only before external creation. External Pinterest Pin ID and internal idempotency key are unique. Reconciliation is required when API outcome is ambiguous.
- `GrowthExperimentStatus`: `DRAFT -> RUNNING -> ANALYZING -> COMPLETED | INCONCLUSIVE`; `PAUSED -> RUNNING`, `CANCELLED`, `FAILED_TERMINAL`. Freeze hypothesis, variants, guardrails and model version at launch.
- `GrowthWarningStatus`: `OPEN -> ACKNOWLEDGED -> RESOLVED`; `OPEN/ACKNOWLEDGED -> SNOOZED -> OPEN`; `DISMISSED` terminal; repeated signal creates occurrence/update without losing history. Warnings recommend, do not disable accounts for performance.
- `GrowthReportStatus`: `DRAFT -> READY -> SENDING -> SENT`; `FAILED_RETRYABLE -> SENDING | FAILED_TERMINAL`; `CANCELLED` before delivery. Provider retry uses stable delivery key and records fallback attempt.
- `GrowthJobStatus`: `PENDING -> CLAIMED -> RUNNING -> SUCCEEDED`; `FAILED_RETRYABLE -> PENDING` at `runAfter`, or `FAILED_TERMINAL`; `CANCELLED`; stale lease -> retry only if attempt budget remains. Unique idempotency key per logical work item.
- `GrowthIdeaStatus`: `DRAFT -> VALIDATING -> PUBLISHED -> ARCHIVED`; failed validation -> `NEEDS_REVISION -> DRAFT`; `PUBLISHED -> REVISING -> PUBLISHED` via a new version; `CANCELLED` before publication. Rollback publishes a prior version as a new version, retaining history.

Every transition has actor kind/id, timestamp, from/to, reason, correlation/idempotency key and checked precondition. Terminal states cannot be reentered in-place; create a new attempt/candidate/version. Database constraints and service-layer compare-and-set enforce transitions; Prisma enums alone do not.

## Attribution and cost calculation contract

Growth Pin URLs include `utm_source=pinterest`, `utm_medium=organic`, a human-readable campaign if useful, and an opaque stable `pin_ref`. Validate against known issued refs; UTM alone never proves an internal Pin. On landing, establish first-party session and record first/last Pinterest touches. Initial configurable attribution window: **7 days from last qualified Pinterest landing**; version this as `pinterest_organic_v1`, store both first- and last-touch fields, and report **last eligible Pinterest touch** as the primary assignment. One qualified conversion per attribution session for the primary KPI after its first trusted SUCCESS translation; additional successes are secondary usage. De-duplicate by server completion/TranslationLog ID and event key. Treat referrer/UTM mismatch, invalid refs, known bots, prefetches, repeat spam and missing logs as quality flags; exclude rather than silently count. Respect consent/legal requirements in deployed regions and keep raw event retention configurable. Aggregates can outlive pseudonymous detail. `cost per qualified conversion = Growth AI spend / qualified conversions` for a matching reporting period, with spend allocation by linked decision/job and a visible unattributed remainder. Never count unknown model pricing as zero actual spend; mark it unpriced.

## Implementation sequencing

Phase 2 implements only `GrowthSettings`, `GrowthJob`, `GrowthActivity` and `GrowthWorkerHeartbeat`, plus `GrowthIntensity`, `GrowthJobType`, `GrowthJobStatus`, `GrowthActivityActorKind` and `GrowthWorkerStatus`, in migration `20261005140000_growth_platform_foundation`. `GrowthJobType` contains only `FOUNDATION_NOOP`; later phases add their own enum values with additive migrations. Settings default to disabled, `BALANCED`, worker batch size 5 (validated 1–25), and the fixed `global` primary key enforces singleton storage. Job payload and activity summary are capped at 8 KiB in services, sensitive-key fields are removed, retries default to three and are capped at five, and the database adds checks for batch size/config version/attempt counts. `GrowthActivity` writes once for each meaningful state transition; its entity/time, creation-time and correlation indexes support audit reads. Historical retention is proposed at 24 months, so Phase 2 needs no cleanup job at its expected foundation volume. Subsequent phases add account/board/OAuth (3), metrics (4), attribution (5), clusters/opportunities (7), content versions (8–9), candidate/asset/experiment (10), approval/publication (11), AI cost/report/warnings (13).
